# Annotated Proposal Outline

Use after resolving `annotated-proposal-outline` through File Templates. Copy the blank master for a new outline; continue a selected draft using [Template adaptation and revision checks](template-adaptation-and-revisions.md). Adapt its headings to the buyer's required response structure.

## 1. Reuse the requirements

Start with the current requirement register or compliance workbook, sources, amendments and company evidence. Keep their IDs and source locators. For missing or changed requirements, use `govtribe-proposal-workflows` reference `references/solicitation-intelligence-and-compliance-extraction.md` from its installed root.

## 2. Organize the response

Follow required volumes, headings, forms and question order. If the buyer supplies no structure, propose headings around the evaluation factors and map relevant PWS/SOW tasks beneath them. Keep buyer-prescribed wording and required response locations, including separate pricing.

Adapt to the procurement:

- **Quote or sealed bid:** prioritize required schedules, forms, acknowledgments and evidence; include narrative where requested.
- **A-E or phased design-build:** follow SF 330 or the current phase's qualifications and criteria.
- **Staff augmentation:** map qualifications, availability and resumes; for outcome-based services, explain delivery processes, capacity and performance controls.
- **Digital products and services:** distinguish product/licensing/authorization evidence from implementation, migration, operations and service commitments.
- **Oral presentations or demonstrations:** create a separate assignment with required scenarios, time, participants and materials.

## 3. Annotate each section

Give writers the evaluator's question; requirement IDs and precise source locators; required content; proposed approach; supporting evidence; owner/SME and dependencies; recommended pages; and useful tables or graphics. Identify missing evidence and unsupported themes instead of filling them with claims. Keep proposed methods distinct from demonstrated performance.

Prioritize mandatory and evaluated content within the buyer's page rules. Label your allocations as recommendations. Carry existing company/capture research forward; use `govtribe-capture-workflows` reference `references/past-performance-match.md` only when project selection is unresolved. Use `govtribe-pricing-data` for unresolved labor/cost assumptions and `govtribe-govcon-writing` for narrative drafting.

## 4. Reconcile and deliver

Map every mandatory instruction and evaluation factor to a response location or visible gap. Apply amendments to all affected sections, evidence requests, assignments and page allocations while preserving accepted content elsewhere. Reconcile shared staffing, schedules, technical boundaries and pricing dependencies.

Use native document capabilities and the adaptation guide to create and inspect the file. Deliver the outline with material gaps and next writing actions; link the existing compliance register instead of requiring another matrix or JSON companion.

For an optional machine-readable outline, `govtribe-proposal-workflows` retains `assets/annotated-proposal-outline-schema.json` and `scripts/validate_annotated_outline.py` at its installed root. That helper checks supplied JSON structure and mappings; use native document checks for the delivered file.
